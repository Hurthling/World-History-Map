## Принятые решения и почему

| Решение | Почему |
|---|---|
| **Никаких правок без прямой команды владельца** (18.10) | Всё сначала ставится в очередь с объяснением; применяется только после явного «применяй». При сомнении — переспросить. |
| Статус «принято» — только по решению владельца (19.10) | Свои предложения Claude помечает «предложение Claude — ждёт решения», иначе владелец их пропускает. |
| Горизонт применения записывается сразу при разборе зоны (21.10) | Чтобы не разбирать одну и ту же зону заново для каждой следующей карты; уже разобранные — дописываются, когда до них дойдём. |
| Даты («сверено») и контур (словами + для построения) записываются при разборе, до решения владельца (21.10) | Раньше одну зону проверяли по 2–3 раза (разбор, очередь, применение) и искали координаты заново при построении; теперь применение — по записи. Владелец градусы не проверяет, поэтому контур описывается ещё и словами. Превью не нужны. |
| Окно ±250 лет — на подтверждение владельцу (20.10) | Карта — снимок на дату, но даты неточны и культура живёт дольше своих находок; спорные края решает владелец по аргументам. |
| Знаков вопроса на карте нет (20.10) | Сомнения — в примечании карточки, решение — за владельцем. |
| Памятник внутри культуры — в карточку, а не отдельной зоной (20.10) | Иначе карта пестрит точками, которые повторяют ту же культуру. |
| Частично разобранная карта: «Нет данных» только в разобранных частях света (20.10); **с карты 5000 — иначе** (владелец 21.11): «Нет данных» вне перенесённых зон по всей карте, под годом «Черновик: разобраны …» | Иначе неразобранный мир выглядел бы «проверенным и пустым»; с 5000 переносится больше 100 наших зон, и подпись честно говорит, что разобрано. |
| **Регламент начала новой карты** (владелец 21.11; `CLAUDE.md` п. 30) | Старт новой карты — в одном порядке: условия → море и озёра → перенос по реестру → новые зоны → исходник → проверка; исходник разбирается после переноса, чтобы видеть, где уже стоит наша зона. Части света — соседями, чтобы сразу покрывать стыки; субрегионы постоянные, чтобы архив и промты были сравнимы между картами. |
| Шаг 3 регламента начала карты (новые зоны из реестра и описи) — в шаге 0 подготовки каждой части света (владелец 21.11, 5000bc-11 б) | Иначе 40–60 контуров рисовались бы за месяцы до разбора своей части света, без соседей, и устаревали бы. |
| Клик выделяет только одну область группы, а не все (20.10) | У областей одной группы разные примечания; подсветка всех выглядела бы так, будто карточка относится ко всем. |
| Штриховка и полосы — линии с `<clipPath>`, а не `<pattern>` (20.10) | Узорные заливки давали мусор в Chrome на Android. |
| **Лицензия всего проекта — GPL-3.0** (владелец 26.10) | Данные границ (historical-basemaps) под GPL-3.0, и всё собранное из них обязано быть под ней же; одна лицензия на код и данные проще смеси. |
| Публикация — GitHub Pages (владелец 26.10; план — `corrections/queue-site.md`, С-1) | claude.ai из России недоступен; GitHub Pages бесплатен, даёт историю версий; Netlify, Vercel, Cloudflare Pages из России работают плохо. |
| Без сборщика и фреймворков: чистый HTML + ES-модули | Проще понять и править; ничего не нужно компилировать. |
| d3 + topojson-client лежат локально в `src/vendor/` | Работает без интернета, не зависит от CDN. |
| SVG, а не Canvas | До ~2000 фигур SVG справляется; проще клики и стили. Если будет тормозить, переходить на Canvas. |
| Ползунок шагает по доступным картам, а не по годам | В данных только 54 снимка; интерполяции границ нет. |
| Цвет считается по хэшу имени державы (SUBJECTO) | Цвет стабилен во времени без ручной таблицы цветов. |
| Одна палитра из 18 цветов для государств и культур (3-87, 21.10; применено 22.10) | В старой палитре из 12 цветов несколько пар были почти неразличимы; одна палитра проще двух. |
| Цвет культуры — вручную в `corrections/colors.json` (3-70, 20.10) | Хэш не знает соседей: разные соседние культуры получали один цвет. Одна культура — один цвет на всех картах. |
| Поле `GROUP` у наших зон — общий цвет для одного населения | Зоны Австралии различаются только местом, а население одно; в карточке поле не показывается, чтобы не писать «под властью». |
| Названия стран: ключ = английское имя из данных | В данных нет ID; английское имя единственное общее поле между эпохами. |
| Состояние года в адресе вида `#y1492` | Допустимы только буквы, цифры и «-» (так требовал прежний хостинг; формат оставлен). |
| Поправки — правилами в `corrections/`, а не правкой готовых файлов | Переживают обновление исходников; видно, что и зачем изменено. Правила ищут фигуры по точке и названию, а не по номеру в файле: номера меняются при обновлении. |
| Наши зоны добавляются после упрощения | Иначе маленькие зоны (эбурри, Железные Ворота) упрощались до треугольников. |
| Древний берег — по сетке ETOPO1 10′, с заливкой океана от Тихого океана | Одинаково и честно для всего мира; закрытые водоёмы (Каспий, Мёртвое море) не «осушаются». |
| «Нет данных» только на разобранных картах | На неразобранных и поздних картах пустая суша значит другое («нет государства»). |
| Земли под ледниковыми щитами — «Не заселено» | Надёжно установленный факт; лёд при этом не рисуется (решение владельца), только помечается суша. Горные ледники не помечаются. |
| «Вилка ±1000 лет» | Если находки той же культуры есть и раньше, и позже даты карты в пределах 1000 лет и нет признаков ухода людей — культура считается существующей без примечания: погрешность дат сама порядка сотен лет. |
| Реки и озёра — современные на всех картах, продлены по шельфу на древних | Точных древних русел никто не знает; продление по уклону дна правдоподобно и честно помечено пунктиром и пометкой под годом. |
| «Не заселено» — только надёжно установленное | Это утверждение о прошлом, а не пробел в данных; спорные случаи (Мадагаскар, Крит) — «Нет данных». |
| Примечания — ключом, тексты в `translations/notes/` | Примечания переводятся так же, как интерфейс. |
| Документация на русском, комментарии в коде на английском | Владелец читает по-русски; английские комментарии привычны любому ИИ и разработчику. |
| Одна культура — один контур; расширение — правкой контура | Иначе на карте видны внутренние границы и одна культура выглядит как несколько; сборка сливает куски одного файла сама. |
| Реки под ледниками прячутся слоем-покрышкой, а не SVG-маской | Маска давала визуальный мусор в Chrome на Android. |
| Карта 1 — «по вероятности», окно 135–110 тыс. лет назад (18.10) | Для 125 тыс. лет назад археологии мало и погрешность дат — тысячи лет; правило карты 2 «строго на дату» здесь бессмысленно. |
| Карта 1: вид — цвет, культура — оттенок, пересечения — полосы (18.10) | Главное на этой карте — какие виды людей где жили; культуры вторичны; полосы честно показывают, что жили оба. |
| Пересечения считает сборка, а не рисуем руками | Контуры зон правятся независимо; общий кусок всегда совпадает с ними. |
| Перед работой с mapshaper сушу режем по линии перемены дат | mapshaper считает карту плоской: ребро от +180° к −180° он читает как линию через весь мир. |
| Местный уровень моря в многоугольнике (`local` в `sea-levels.json`, 24.10) | Сетка 10′ мельчит мелкие моря (Бассов пролив, Карпентария); общий уровень моря там дал бы сушу, которой не было. |
| Свои уровни Каспия, Чёрного и Азовского морей и Балтики (`basins` и `local`, владелец 27.10) | Они не были связаны с океаном (или вода стояла выше океана); по реконструкциям ≈ 10–12 тыс. лет назад их уровни были другими. Уровни приблизительные — так и подписано под годом. |
| Порог «один цвет» — 2000 км (владелец 27.10, 3-188) | Одинаковые зоны на расстоянии 1500–2000 км легко соединить взглядом (особенно через море) и принять за одну культуру. Старые пары не перекрашиваем без запроса. |
| Резервная копия — версия в git, а не архив (владелец 27.10, С-4) | Git хранит весь проект и любую прошлую версию; архив дублировал его. Версию перед пакетом сохраняет владелец. |
| Легенда складная на всех картах (С-3, владелец 27.10) | Её можно убрать, чтобы не закрывала карту; на картах «по находкам» по умолчанию открыта — новичку сразу видно, что значит штриховка. |
| Наши проверки — не в карточки (владелец 28.10, 3-193) | «Это наши исследовательские истории, не надо на карту всё тащить»: опровергнутые даты и ход разбора остаются в очереди, в карточке — только о самой зоне. |
| Маленькая зона — поверх соседней, не обрезать (владелец 28.10, п. 138) | Маленькие зоны и так плохо видно; граница в то время — условность. Исключение: круг накрывает памятник другой культуры — граница посередине между памятниками. |
| Граница зоны по находкам (владелец 30.10, 6-37) | С «Нет данных» — оболочка находок + 50 км; между двумя зонами — середина между ближайшими находками, если полосы «+50 км» сходятся, иначе между ними «Нет данных». Находки — только с датами (база «на дату», «по вилке», принятые ±250); без точных координат — центр района. Применено к Техасу и краям равнин; прямые по параллелям ничем не обоснованы. |
| Длинные подписи — в несколько строк (владелец 30.10, С-5) | Длинные имена налезали на соседние зоны и подписи; больше 30 знаков — 2 строки, каждые следующие 30 — ещё строка; скобки в конце — по возможности целиком последней строкой, сами скобки не считаются. |
| Попутный разбор источников (владелец 02.11) | В источнике владельца сверяются все даты со всеми картами: по разобранным и разбираемым — проверка и пункт очереди, по неразобранным — заготовка. Иначе находки из уже прочитанных статей теряются и статьи приходится перечитывать. |
| Проверка пропусков «база против зон» (владелец 02.11) | Карты 10 000 и большая часть 8000 (Африка, Америки) разбирались до правила «даты сначала из базы» (21.10). При разборе каждой новой части света на 6000\* заодно сверяем базу с зонами на 10 000 и 8000; обе Америки — разовым прогоном (их 6000\* уже разобраны). К разобранным частям 6000\* не возвращаемся. |
| Русские названия — по мере проверки карт (владелец 13.11, С-7) | Переводим только проверенные карты: на непроверенных названия ещё поменяются. Латинские названия видов (Homo sapiens и др.) не переводим, народы — во множественном числе с заглавной. |
| Опись дат из источников — все встреченные даты в одной таблице (владелец 16.11; `corrections/source-dates.tsv`) | Чтобы при промежуточных картах не перечитывать источники: даты всё равно выписываются при проверке, запись почти ничего не стоит; это опись, а не решение. |
| Реестр зон — опись наших зон: годы существования и ареал на каждой карте (владелец 15.11; `docs/zones-registry.md`) | Горизонт записывался текстом в разных пунктах и плохо отбирался для новой карты; годы «Начало» / «Конец» позволяют отобрать зоны скриптом. Главный остаётся `corrections.json`, реестр сверяет сборка. |
| Регламент обработки таблицы части света (владелец 17.11; `CLAUDE.md` п. 27) | Собирает в один порядок прежние правила (п. 20, 21, 24, 26): хвосты → источники → пустоты по базе → добивка в каждом чате, прошлые карты — один раз в конце части света, чтобы не проверять одну культуру дважды. Опись и реестр — вспомогательные файлы, их Claude ведёт сам; новые зоны в реестр — только при «применяй» (сборка сверяет реестр с картой). Применять — примерно каждый второй чат: каждый субрегион отдельно — слишком много хлопот и границы с неразобранными соседями пришлось бы двигать, вся часть света разом — огромный пакет и устаревшие решения. |
| **Экономный режим** (владелец 20.11, этап 42; `CLAUDE.md` п. 29) | Ретроспектива: Африка ≈ 80 % недельного лимита против ≈ 25 % у Северной Америки — из-за чтения 130 PDF целиком и больших файлов, которые перечитывал каждый чат. Один файл на зону, выдержки, очередь только с открытым. |

## Известные ограничения

- Реки и озёра современные; из исчезнувших озёр показаны Агассис на карте 8000 (контур приблизительный) и Мега-Чад на 8000, 6000\* и 5000
  (с 21.11, по сетке ETOPO, отметка 339 м); озёра «зелёной Сахары» и смены русел (Хуанхэ, Амударья) пока не показаны.
- **Море на нынешней суше** (с 21.11, этап 47) — только Ботника и Фенноскандия, Гудзонов залив и арктический берег Канады (5000, 6000\*), вершина Персидского залива (5000);
  контуры приблизительные (сетка 18 км, модель Påsse, срезы Dyke); Белое море и Кольский п-ов — как сейчас (точек модели нет).
- **Карта 5000 — черновик:** берег современный, кроме Ботники, Гудзонова залива и вершины Персидского залива (этап 47).
- **Уровни замкнутых морей приблизительные** (Каспий, Чёрное и Азовское, Балтика на картах 10 000 и 8000): по реконструкциям, точнее источники не дают.
- **Шум на телефоне:** исправление (линии вместо узоров) сделано 20.10; на настоящем Android ещё не проверено.
- Низины ниже уровня моря, не связанные с океаном на сетке 10′ (дельта Сакраменто, части Сундского шельфа), на древней карте
  остаются водой (так строится берег: замкнутые котловины не «осушаются»). Мелкие ошибки, на глаз почти не видны.

- Цвета государств выбираются по названию без учёта соседей, поэтому соседи иногда одного цвета
  (например, Германия и Австро-Венгрия в 1914). Возможное улучшение — раскраска с учётом соседства.
  У культур Азии и Европы карты 10 000 цвета пока тоже по хэшу (Европа карты 8000 и три культуры Северной Америки — вручную с 24.10) — сборка печатает предупреждения
  (`colour …`); Северная Америка — пункт 3-71.
- Только 54 снимка: между ними карта «прыгает».
- При сильном приближении границы угловатые (упрощение до 8%).
- Данные historical-basemaps — работа в процессе: есть ошибки и пробелы (например, в 323 г. до н. э. почти пустая Европа).
- Названия по-русски — только на картах 123 000, 10 000, 8000, 6000\* и 5000; на остальных 50 картах — английские.
