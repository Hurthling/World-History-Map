### С-4. Резервные копии перед пакетом — вместо архивов `backup-before-*.tgz` версия в git — статус: **принято (владелец 27.10)**, правило действует

- **Вопрос владельца (27.10):** GitHub хранит все версии — может быть, отдельные резервные копии не нужны?
- **Ответ:** да, они дублируют git. Каждая версия (`git commit`) хранит весь проект — код, правила, очереди, документы и готовые `data/`; откатить любой файл или всё сразу можно
  из истории (GitHub Desktop → History, или командой). Копия на GitHub появляется после «Push origin», но и без неё история лежит в самой папке (`.git`).
  В git не попадают только `Источники/`, `Claude outputs/`, `node_modules/`, `tools/.cache/` — их я при применении не трогаю (кэш скачивается заново).
- **Предложение:** (1) перед «применяй» вместо архива — проверить, что в git нет несохранённых изменений, и если есть (обычно очереди и `PROGRESS.md` после разбора) —
  сохранить их отдельной версией «Очереди перед пакетом …»; тогда откат пакета — возврат к этой версии. Архив `backup-before-*.tgz` больше не делать.
  (2) Архив `mapw-*.tgz` (рабочая копия, которую я переношу в облако для сборки и снимков) — не резервная копия; удалять его сразу после пакета.
  (3) Старые архивы в `Claude outputs/` — 12 файлов `.tgz`, ≈ 96 МБ (бэкапы 22.10 … 27.10, рабочие копии) — можно удалить; всё их содержимое есть в git, кроме совсем ранних
  (до 26.10, когда git ещё не было: `backup-before-22.10`, `-24.10`, `-24.10b`, `map-stage12`, `map1-stage10`, `sync-20.10`) — их оставить или удалить на твоё усмотрение.
- **Решение владельца (27.10):** правило работает, но **перед тем как сохранять отдельную версию — сказать владельцу, он сохранит сам** (Claude версию «перед пакетом» не делает).
  Архивы `backup-before-*.tgz` больше не делаются; рабочий `mapw-*.tgz` — удалять после пакета. Старые архивы (п. 3) — не трогаем, пока владелец не скажет.
  Записано в `CLAUDE.md` (п. 14) и `PROGRESS.md` (27.10).
