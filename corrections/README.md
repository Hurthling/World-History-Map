# Поправки к исходным данным

Исходные карты берутся из чужого проекта (historical-basemaps) и в них есть ошибки.
Мы не правим их напрямую: все исправления записаны правилами в `corrections.json`,
и скрипт сборки (`npm run build-data`) накладывает их перед упрощением карт.
Так поправки переживают обновление исходных данных, и видно, что и зачем изменено.

После изменения `corrections.json` нужно пересобрать данные: `npm run build-data`.
Скрипт напечатает по каждому правилу, сколько фигур оно затронуло. Если написано
`NOTHING MATCHED`, правило ни на что не подействовало и его надо проверить.

## Формат правила

```json
{
  "id": "switzerland-name",
  "why": "Почему нужна правка (для людей)",
  "years": [1994, 2000, 2010],
  "action": "set",
  "where": { "containsPoint": [7.45, 46.95], "NAME": "" },
  "set": { "NAME": "Switzerland", "SUBJECTO": "Switzerland", "PARTOF": "Switzerland" }
}
```

| Поле | Значение |
|---|---|
| `id` | короткое уникальное имя правила |
| `why` | объяснение |
| `years` | список лет или `"all"` (до н. э. — отрицательные: `-500`) |
| `action` | `"set"` — поменять поля; `"remove"` — удалить фигуру |
| `where` | какие фигуры затронуть (все условия должны выполняться) |
| `set` | новые значения полей (только для `"set"`) |

Условия в `where`:

| Условие | Смысл |
|---|---|
| `"NAME": "France"` | название совпадает; `""` — фигура без названия |
| `"containsPoint": [долгота, широта]` | фигура накрывает эту точку. **Сначала долгота!** Координаты удобно брать в Google Maps (там порядок обратный: широта, долгота) |
| `"maxAreaKm2": 100` | площадь меньше (км²) |
| `"minAreaKm2": 100` | площадь больше (км²) |

Правила применяются по порядку сверху вниз.

## Новые зоны (культуры): действие `add`

```json
{
  "id": "m2-swiderian",
  "why": "Map 2, item 2.",
  "years": [-10000],
  "action": "add",
  "shape": "swiderian",
  "properties": { "NAME": "Swiderian culture", "NOTE": "swiderian", "SOURCES": "https://… | https://…" }
}
```

| Поле | Значение |
|---|---|
| `shape` | файл контура `corrections/shapes/<shape>.geojson` (многоугольник, координаты «долгота, широта») |
| `properties.NAME` | название (по-английски; перевод — в `translations/names/`) |
| `properties.NOTE` | ключ примечания; сам текст — в `translations/notes/en.json` и `ru.json` |
| `properties.SOURCES` | ссылки на источники через ` \| ` — показываются в карточке |
| `clipToLand` | `false`, если зону не надо обрезать по суше (по умолчанию обрезается по суше этого года, с древним берегом) |
| `simplify` | упростить зону после обрезки по суше, например `"15%"` (доля оставленных точек): для больших зон вдоль подробного берега (так сделаны «Не заселено» карты 1, п. 1-25) |

Контур можно нарисовать или поправить мышью на https://geojson.io (открыть файл, отредактировать, сохранить).

**Точечная зона — круг радиусом не меньше 35 км** (решение владельца 22.10, п. 3-88; «день пути пешком: в этом радиусе люди точно
присутствовали и действовали»). Круги больше 35 км не трогаем; квадраты-острова «Не заселено» и зоны не круглой формы — не относятся.

**Маленькая зона — поверх соседней, не обрезать (решение владельца 28.10, п. 138).** Круг или другую маленькую зону рисуем поверх большой зоны соседней культуры целиком: маленькие зоны и так плохо видно,
а граница в то время — условность. Исключение: если круг накрывает конкретный памятник другой культуры, граница между ними — посередине между двумя памятниками.

**Одна культура — один контур (решение владельца 18.10).** Если зону расширяем, правим её контур, а не добавляем
рядом отдельный кусок: иначе на карте видны внутренние границы и зона выглядит как несколько областей.
Сборка это страхует: все фигуры одного файла `shapes/<shape>.geojson` сливаются в одну (соприкасающиеся
и перекрывающиеся — без внутренних границ). Отдельными частями остаются только места, разделённые
пустым пространством без находок (например, Федерзе и Альпштайн, Хауа-Фтеах отдельно от Магриба).
Зоны добавляются **после** упрощения карты (чтобы маленькие зоны не превращались в треугольники) и рисуются поверх,
в порядке правил. Граница всегда помечается «приблизительные».

## Общий цвет: поле `GROUP`

Зоны с одинаковым `"GROUP"` в `properties` красятся одним цветом (например, все зоны Австралии и Тасмании —
`"Sahul — Australia"`). В карточке поле не показывается. Им же можно развести цвета соседних зон, если они
случайно совпали по хэшу названия.

## Цвет вручную: `colors.json` (п. 3-70, 3-87)

Палитра одна для государств и культур — 18 цветов (`--polity-0 … --polity-17` в `src/styles.css`, светлая и тёмная темы).
Обычно цвет выбирается по хэшу имени (`GROUP`, иначе `SUBJECTO`, иначе `NAME`). Для культур цвет можно задать вручную:
`corrections/colors.json`, раздел `colors` — ключ: `GROUP` зоны (или её `NAME`, если группы нет), значение — номер цвета.
Сборка пишет его в поле `COLOR`. Одна культура — один номер на всех картах; если на одном месте одна культура сменяет другую,
номера разные (чтобы не читалась преемственность). Сейчас так заданы Африка (10 000 и 8000), Южная Америка (10 000 и 8000), Европа (8000; подобрано скриптом 24.10), три культуры Северной Америки (3-71), Сибирь и Дальний Восток (8000 и новые зоны 10 000; подобрано скриптом 26.10) и пункты 114–116 карты 10 000. Сахул — по хэшу групп «Sahul — Australia» и «Sahul — New Guinea», как на 10 000.
При каждой сборке `tools/check-colors.mjs` проверяет разобранные карты и печатает строки `colour …`: один цвет у зон ближе
≈ 1500 км (`same colour`) или похожие цвета (`similar colours`, различие меньше 10 по OKLab) у соседей ближе ≈ 1500 км.
Если ключ из `colors.json` не нашёл ни одной зоны — сборка пишет `! corrections/colors.json: … matches no zone`.

## Группа областей: поля `NAME` и `AREA`

Несколько зон одной группы (например, все зоны Австралии) получают общее `NAME` — по нему одна подпись на карте
и общий цвет, — а своё имя области кладётся в `"AREA"`. Карточка: заголовок — `AREA`, под ним — `NAME`;
клик выделяет только эту область.

## Карта 1: вид и культура — поля `SPECIES` и `CULTURE`

У зон карты 1 (123 000 г. до н. э.) `SPECIES` — вид человека (`sapiens`, `neanderthal`, `denisovan`, `erectus`,
`floresiensis`, `luzonensis`, `unknown` — «вид не установлен»): он задаёт основной цвет. `CULTURE` — археологическая
культура (`msa`, `aterian`, `nubian`, `levantine-mousterian`, `mousterian`, `taubachian`, `altai-mp`): оттенок цвета вида.
Какой культуре какой оттенок — таблица `SHADES` в `src/colors.js`; сами цвета — `--sp-<вид>-<0…4>` в `src/styles.css`
(0 — вид без названной культуры). `NAME` — название вида (одна подпись на карте), `AREA` — область или культура
(заголовок карточки).

**Пересечения** сборка находит сама (`tools/overlaps.mjs`): если зоны разных видов (или разных культур одного вида)
накладываются, общий кусок вырезается отдельной фигурой (`KIND: "overlap"`) и рисуется вертикальными полосами двух цветов;
клик по нему показывает обе зоны. Куски меньше 500 км² (общие границы) не считаются.

Контуры `m1-*` построены по контурам стран Natural Earth (world-atlas) с обрезкой прямоугольниками и линиями
(Днепр, Евфрат, Нил); их можно править на geojson.io, как и остальные.

## «Не заселено»: поле `KIND`

Зона с `"KIND": "uninhabited"` в `properties` рисуется отдельным ровным цветом (без подписи на карте),
в карточке — «Не заселено» и примечание с датой первого заселения. Только для надёжно установленных случаев.
Сюда же относятся земли под ледниковыми щитами (примечание `uninhabited-ice`): лёд не рисуется, помечается только суша.

## Разобранные карты: `reviewed.json`

Годы, карты которых проверены по научным источникам:
- `years` — карты «по находкам»: пустая суша заштрихована как «Нет данных» (клик — карточка «Нет данных»),
  своя легенда. Сейчас: −10000 и −8000 (вся карта 8000 разобрана 27.10, п. 3-186).
- `probability` — карты «по вероятности»: закрашено, если присутствие вида вероятнее 50 %; штриховки нет,
  клик по пустой суше — карточка «Вероятность ниже 50 %», легенда видов. Сейчас: −123000.
- `regions` — карта, разобранная только частично (сейчас таких нет; карта 8000 была разобрана по частям света до 27.10 — её последний контур
  лежит в `corrections/archive/regions/reviewed-8000.geojson`):
  контур разобранных частей света (`corrections/regions/<имя>.geojson`) и ключ подписи в легенде. Штриховка «Нет данных»
  и карточка «Нет данных» — только внутри этого контура (сборка пишет `data/coast/reviewed_<год>.json` = суша года ∩ контур);
  в остальном мире — данные исходника без штриховки.
- `coastNotes` — ключ подписи под годом (тексты в `translations/ui/`), например `coastModernHigher` для карты 1:
  «Береговая линия современная (море было на 6–9 м выше)». На карте с древним берегом подпись идёт отдельной строкой под уровнем моря
  (карты 10 000 и 8000 — `seaLevelsApprox`: «Уровни Каспия, Чёрного и Балтийского морей — приблизительные»).

## Древняя береговая линия: `sea-levels.json`

Для лет из этого файла берег строится по уровню моря эпохи (например, `"-10000": -60` — на 60 м ниже нынешнего).
Как строится — `tools/coast.mjs`. Ледниковые щиты не рисуем (решение владельца), проседание суши под ледниками не учитываем.
Чёрное и Азовское моря на сетке 10′ отрезаны от океана, поэтому общий уровень моря их не трогает (в то время это и был отдельный водоём);
с 27.10 у них свой уровень — см. «Замкнутые моря» ниже. Балтика и Персидский залив связаны с океаном и понижены вместе с ним; у Балтики с 27.10
свой местный уровень (см. ниже).

Замкнутые водоёмы внутри материка (Каспий) сохраняются: при разрезке суши по линии перемены дат (`flatLand` в `tools/coast.mjs`)
дыры фигур, пересекающих эту линию, вырезаются из суши заново (п. 3-89 / 112, 24.10; раньше Каспий на картах 10 000 и 8000 пропадал).

**Местный уровень моря** (поле `local`, п. 3-112 и 113 карты 10 000, 24.10): сетка 10′ делает некоторые мелкие моря ещё мельче, чем они есть
(Бассов пролив, залив Карпентария). Для таких мест задаётся многоугольник (`area`, «долгота, широта») и свой уровень (`level`): внутри него ячейка —
вода, если она глубже этого уровня. Сейчас: на 8000 — Бассов пролив (−25 м; Тасмания — остров) и залив Карпентария (−15 м; залив — море),
на 10 000 — озеро Карпентария (−25 м; северный берег озера — по линии о-ва Уэссел — Кейп-Йорк, у порога Арафура).
С 27.10 (п. 3-187, 127) так же сделана Балтика: к югу от линии Кальмар — Лиепая (56,6° с. ш.) — −28 м на 8000 (Анцилловое озеро) и −25 м на 10 000
(Балтийское ледниковое озеро); к северу — уровень 0 (нынешний берег: тогда вода стояла даже шире). Каттегат — по общему уровню.

**Замкнутые моря** (поле `basins`, п. 3-186, 3-187 карты 8000 и 126, 127 карты 10 000, 27.10): Каспий и Чёрное море на сетке не связаны с океаном,
поэтому им задаётся свой уровень: `level` — уровень моря, `seed` — точка в море, `area` — многоугольник, `today` — нынешний уровень этого моря
(Каспий — −27, с запасом к −28 м; Чёрное — 0). Сборка находит нынешнее море (ячейки, связанные с `seed` и глубже `today`, внутри `area`);
из них вода — глубже `level`, остальное — суша; прочие низины внутри `area` (Прикаспийская низменность, Карагие) — суша. Реки, впадающие
в такие моря, продлеваются по осушённому дну до нового берега (`tools/hydro.mjs`). Сейчас: Каспий −45 м (8000) и −50 м (10 000, мангышлакская регрессия);
Чёрное и Азовское −30 м (8000) и −40 м (10 000) — Азовское море суша. Под годом — подпись «Уровни … приблизительные» (`coastNotes`).

Исчезнувшие озёра (поле `lakes`, например `"-8000": ["agassiz-8000"]`): контуры в `corrections/lakes/`, вырезаются из суши
этого года так же, как море (зоны, штриховка и клики их не задевают). Сейчас: приледниковое озеро Агассис на карте 8000.

## Правила работы с древними картами (решения владельца)

- **Ничего не применяем без прямой команды владельца.** Каждое предложение (в том числе найденное попутно)
  сначала записывается в очередь с оценкой; правка в `corrections.json`, контурах и коде — только после явного «применяй».
  Сомневаешься, разрешено ли, — переспроси.

- Зону рисуем только там, где есть подтверждённые находки.
- Культура попадает на карту, только если существовала **строго на дату карты**; даты — в календарных годах
  (радиоуглеродные пересчитываем). Исключения отмечаются примечанием в карточке.
- Точные границы не рисуем, все зоны «приблизительные».
- **Правило «вилки» (±1000 лет):** если прямой находки ровно на дату карты нет, но у той же стоянки или культуры
  в том же районе есть датированные находки и раньше, и позже даты карты, каждая не дальше 1000 календарных лет
  (считаем по ближнему краю диапазона дат), и нет свидетельств, что люди уходили (перерыв в слоях, стерильный слой,
  вывод авторов о забрасывании), — считаем, что культура на дату существовала, и отдельное примечание об этом не ставим.
  Если находки только с одной стороны или дальше 1000 лет — примечание остаётся.
- **Окно ±250 лет (решение владельца 20.10).** Карта — снимок на дату. Но погрешность дат и то, что культура могла
  существовать раньше первых и позже последних находок, учитываются так: культуры, чьи первые или последние находки лежат
  в пределах ±250 калиброванных лет от даты карты, Claude разбирает отдельно и даёт владельцу на подтверждение (с аргументами
  «за» и «против»). Если есть байесовская модель границ культуры — опираться на неё, а не на первую/последнюю находку.
  Старые обычные радиоуглеродные даты с большой погрешностью — повод разбираться, а не решение. Правило «вилки» остаётся в силе.
- **Горизонт применения (решение владельца 21.10).** Разбирая зону для карты, сразу определяем, на каких картах она будет
  стоять дальше (из существующих и будущих: 10 000, 8000, 6000\*, 5000, 4000, 3000 …), и записываем это в пункт очереди
  строкой **«Горизонт:»** — где зона стоит, в каком виде (тот же контур / шире / уже / сменяется другой культурой), где
  кончается и почему (с источником). Цель — не разбирать ту же зону заново для каждой следующей карты: на следующей карте
  её переносим по записи. Повторно разбираем, только если появились новые данные или край горизонта попадает в окно
  ±250 лет от даты карты (тогда — на подтверждение владельцу, как обычно).
  Уже разобранные зоны задним числом не перепроверяем: горизонт им записываем, когда дойдём до них при разборе следующей карты.
  Строка «Дальше» в старых пунктах — прогноз; там, где стоит «проверить», это ещё не горизонт.
- **Строки «Даты:» и «Контур:» — при разборе, не при применении (решение владельца 21.10).** Цель — не искать одно и то же
  несколько раз (при разборе, при формировании очереди, при применении). Каждый новый пункт очереди, где зона ставится или
  меняется, до того как уйти владельцу на решение, содержит:
  - **«Даты: сверено <дата>»** — даты так, как в источнике (радиоуглеродные и калиброванные), сам источник; все «сверить»
    в пункте к этому моменту закрыты. Не удалось (нет доступа к статье) — это вопрос владельцу, а не задача на применение;
  - **«Контур:»** — две части. *Словами* — для владельца, без градусов: города, реки, горы, страны («долина реки X от города A
    до порогов B, в горы не заходит»). *Для построения* — для Claude: памятники с координатами (широта, долгота), из каких
    контуров стран или областей собирается зона, чем обрезается, на сколько выходит за крайние находки; если вариантов
    несколько — контур для каждого варианта.
  При применении пункт с этими строками строится **по записи, без повторного поиска**. Повторно ищем, только если появились
  новые данные или нашлось противоречие с соседним пунктом (окно ±250 — по-прежнему на решение владельца).
  Превью-картинки зон не делаем. Действует для новых пунктов; уже принятые (Южная Америка карты 8000, 3-75 … 3-87,
  и всё раньше) задним числом не дописываем — применяем по-старому.
- **Разбор — в чат (решение владельца 24.10).** Владельцу неудобно искать новые пункты в папке и читать сплошной текст очереди.
  Поэтому после разбора новые пункты, кроме записи в очередь, выводятся в чат текстом, по каждому пункту одинаково:
  1) номер пункта и название зоны; 2) факты кратко — что найдено и даты; 3) предложения Claude — варианты и рекомендация;
  4) решения, которые нужны от владельца (если нет — «решать нечего»); 5) контур словами (без градусов); 6) горизонт.
  Координаты, правила построения и полный список источников остаются только в файле очереди.
  Пункты выводятся **строго по возрастанию номеров очереди** (решение владельца 26.10: иначе легко пропустить пункт).
- **Сибирь и Дальний Восток — отдельная часть света (решение владельца 26.10).** Сибирь и Дальний Восток — отдельная «часть света»: Россия к востоку от Урала (по той же линии, где кончается разобранная Европа) до Тихого океана, с Сахалином, Курилами, Камчаткой, Чукоткой и островами Арктики. Владелец даёт предложения по ней отдельно от остальной Азии. Граница с Европой — та же линия по Уралу, что в контуре
  разобранной Европы; южная граница — граница России (зоны у границы могут заходить за неё, но штриховка «Нет данных» при частичном разборе кончается на границе).
- **Даты — сначала из базы (решение владельца 21.10).** Разбирая часть света, сначала запускаем `tools/c14.mjs` по району
  (база p3k14c ≈ 175 тыс. дат, калибровка IntCal20/SHCal20, вердикт «на дату / вилка ±1000 / нет» и пометка окна ±250):
  `node tools/c14.mjs --year -8000 --box W,S,E,N --brief` — обзор стоянок; `--site <имя>` или `--near ШИР,ДОЛГ --km 50` —
  даты конкретной стоянки. Веб-поиск — только для того, чего в базе нет (новые работы, стоянки без дат в базе), и для
  толкования: к какой культуре относится слой, есть ли перерыв, что пишут авторы. Перерывы внутри последовательности скрипт
  не ищет — смотреть по списку дат. Морские раковины помечены ⚠ (резервуарный эффект не учтён). В строке «Даты: сверено …»
  указывать «p3k14c + `tools/c14.mjs`» и исходную публикацию (её скрипт выводит в «Источники»).
- **Наши проверки — не в карточки (решение владельца 28.10, п. 3-193).** Опровергнутые даты, ложные следы и ход нашего разбора («даты Марацци отвергнуты», «Кампо-Лаборде передатирован») на карту не выносим —
  они остаются в очереди. В карточке — только то, что говорит о самой зоне.
- **Знаков вопроса на карте не ставим (решение владельца 20.10).** Claude приводит аргументы, решает владелец;
  сомнения — в примечании карточки.
- **Памятники внутри культуры отдельно не красим (решение владельца 20.10).** Если памятник лежит на территории культуры
  и не выбивается из неё — он упоминается в карточке зоны, а не рисуется отдельной зоной.

- **Карта 1** (решения владельца 18.10): окно дат 135–110 тыс. лет назад вместо «строго на дату»; закрашиваем, если
  присутствие вида вероятнее 50 %; без «Нет данных»; береговая линия современная. Подробности — `queue-map1.md`.
