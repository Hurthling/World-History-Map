## Как всё работает (поток данных)

1. `index.html` загружает стили, библиотеки d3 и topojson, затем `src/main.js`.
2. `main.js` загружает языки (`translations/`) и список лет (`data/index.json`).
3. Создаются три части интерфейса: карта (`map.js`), ползунок (`timeline.js`), карточка (`infopanel.js`).
4. Все изменения идут через `state.js`: например, ползунок вызывает `state.set({ year })`.
5. `main.js` подписан на изменения состояния и обновляет нужные части:
   - сменился год → загрузить `data/borders/world_<год>.json` → перерисовать карту;
   - сменился язык → загрузить переводы → обновить тексты и подписи;
   - выбрана страна → подсветить её и показать карточку.

## Данные

Исходник: [historical-basemaps](https://github.com/aourednik/historical-basemaps), GPL-3.0.
Рельеф и глубины для древнего берега: ETOPO1 (общественное достояние) в выборке 10′ от fatiando-data (CC-BY 4.0),
скачивается автоматически в `tools/.cache/etopo/`.
Поля каждой страны:

| Поле | Что значит |
|---|---|
| `NAME` | название страны, региона или культуры (по-английски) |
| `SUBJECTO` | держава, которой подчинена территория (по нему выбирается цвет) |
| `PARTOF` | более крупная культурная область |
| `BORDERPRECISION` | 1 приблизительные, 2 довольно точные, 3 по договору |

Порядок сборки: древний берег (`coast.mjs`) → исходник → правки set/remove → упрощение →
наши зоны (`add`: куски одного файла сливаются в один контур, обрезаны по суше года) поверх → `data/borders/`. В `data/index.json` у года с древним берегом
есть поля `land` (файл суши) и `seaLevel` (уровень моря) — страница берёт фон из них и пишет уровень моря под годом.

Дополнительные поля наших зон: `NOTE` (ключ примечания), `SOURCES` (ссылки) — показываются в карточке;
`GROUP` — группа цвета у наших зон (одинаковая группа — один цвет; в карточке не показывается; `src/colors.js`).
`COLOR` — номер цвета в общей палитре, заданный вручную (`corrections/colors.json`, по `GROUP`, иначе по `NAME`; пишет сборка).
Палитра одна для государств и культур: 18 цветов `--polity-0 … --polity-17` (`src/styles.css`); без `COLOR` номер — хэш имени
(`paletteIndex` в `src/colors.js`). Соседей одного или похожего цвета на разобранных картах ищет `tools/check-colors.mjs`.
`AREA` — имя одной области внутри группы зон с общим `NAME`: выбор хранится ключом `NAME::AREA`
(`selectionKey` в `map.js`), карточка показывает `AREA` заголовком и `NAME` подзаголовком (`infopanel.js`).
Подписи (`labels.js`): каждое имя подписывается один раз — на самом большом куске, центр которого виден на экране.
`SPECIES` и `CULTURE` (карта 1) — вид человека и археологическая культура: цвет вида и его оттенок
(`speciesColor` в `colors.js`, цвета `--sp-*` в `styles.css`). `KIND: "overlap"` — пересечение двух зон
(`tools/overlaps.mjs`, поле `PARTS` — ключи обеих зон): рисуется узором из вертикальных полос (`drawStripePatterns`
в `map.js`), карточка показывает обе зоны (`showOverlap` в `infopanel.js`).
`KIND: "uninhabited"` — незаселённая территория (свой цвет, без подписи). У года «по вероятности» (карта 1) в `index.json` стоит `mode: "probability"`
(и `coastNote` — подпись под годом): нет штриховки, клик по пустой суше — карточка «Вероятность ниже 50 %»
(`state.LOW_PROB`), своя складная легенда (`#legend-prob`). У разобранного «по находкам» года в `index.json`
стоит `reviewed: true`: пустая суша штрихуется (`#hatch-nodata` в `map.js`), клик даёт карточку «Нет данных»
(`state.NO_DATA`), показывается легенда (`#legend` в `index.html`).
Если карта разобрана только частично (`reviewed.json` → `regions`), в `index.json` есть `reviewedArea` (файл суши разобранных
частей) и `reviewedNote` (ключ подписи в легенде, `#legend-part`): штриховка и карточка «Нет данных» — только там
(`setReviewedArea` в `map.js`).
**Штриховка и полосы рисуются линиями, а не узором** (`<pattern>`): линии на всю видимую часть экрана, обрезанные
по контуру через `<clipPath>` (`#clip-nodata` — пустая суша или разобранные части; у каждого пересечения карты 1 — свой),
перестраиваются при каждом масштабе, чтобы шаг на экране не менялся. Узорные заливки (как раньше SVG-маска) давали
мусор в Chrome на Android. Безымянные фигуры исходника на разобранных картах прозрачны, чтобы штриховка под ними была видна.
Ошибки в данных исправляются только через `corrections/corrections.json`, не правкой `data/`.

Реки и озёра (`tools/hydro.mjs`): Natural Earth 1:50 млн, у каждой реки и озера поле `r` (важность, 1 — крупнейшие).
Страница рисует их слоем над зонами (`map.js`: слои `lakes`, `rivers`), мелкие реки — только при приближении
(`CONFIG.rivers` в `config.js`); ранги подогнаны так, чтобы видимый приток не впадал в скрытую реку или озеро.
Под зонами с примечанием `uninhabited-ice` (ледники) реки скрыты: эти зоны нарисованы ещё раз поверх рек
(слой `ice-cover` в `map.js`; SVG-маска давала мусор на Android).
Для лет с древним берегом в `index.json` есть поле `riversExt` — продления рек по осушённому шельфу (пунктир):
от устья (сначала по сегодняшнему эстуарию, если он уже ячейки сетки) по уклону дна до древнего моря,
рукава дельт сливаются в одно русло, линия обрезана ровно по нарисованному берегу.

Современная суша (world-atlas) хранится «на шаре»: несколько контуров пересекают линию перемены дат
(Чукотка, о. Врангеля, Фиджи, Антарктида). Для mapshaper её режут по 180° (`flatLand` в `coast.mjs`),
иначе при сборке древнего берега появлялись ложные полосы суши вдоль 71° с. ш. и 16,5° ю. ш.
При этой разрезке терялись дыры фигур (у Евразии — Каспий), поэтому они собираются отдельно и вырезаются из суши после разрезки
(п. 3-89 / 112, 24.10).
Там, где сетка 10′ мельчит мелкие моря, в `sea-levels.json` → `local` задаётся многоугольник со своим уровнем моря: внутри него глубина
сдвигается так, что вода — всё глубже местного уровня (`buildCoasts` в `coast.mjs`; п. 3-112 и 113 карты 10 000).

Пересобрать данные: `npm install`, затем `npm run build-data`.
**Важно (22.10):** сборка падает (`h5wasm … Assertion failed`), если путь к папке проекта содержит кириллицу («Карта мира»):
библиотека чтения глубин не принимает не-ASCII в переменных окружения. Поэтому собирать из копии по латинскому пути: скопировать
проект (без `Источники`, `Claude outputs`) в, например, `/tmp/mapw`, запустить там `node tools/build-data.mjs` (≈ 30 с) и вернуть
папку `data/` обратно. Сборке нужно разрешение на удаление файлов (она пересоздаёт `data/borders` и `data/coast`).
Степень упрощения меняется переменной `SIMPLIFY` (по умолчанию `8%`).

## Как сделать типичные изменения

| Хочу… | Где менять |
|---|---|
| Изменить год при открытии, скорость проигрывания, количество подписей | `src/config.js` |
| Изменить цвета | `src/styles.css`, блок `:root` и тёмная тема ниже; цвет отдельной культуры — `corrections/colors.json` |
| Добавить язык или перевести названия | `translations/` (инструкция в `translations/README.md`) |
| Добавить поле в карточку страны | `src/infopanel.js` (+ текст подписи в `translations/ui/*.json`) |
| Изменить подписи на ползунке | `src/timeline.js`, массив `LANDMARKS` |
| Исправить страну на карте (название, принадлежность, лишняя фигура) | `corrections/corrections.json`, затем `npm run build-data` |
| Добавить культуру (зону) на карту | контур в `corrections/shapes/`, правило `add`, примечание в `translations/notes/` |
| Древний берег для ещё одного года | `corrections/sea-levels.json` (реки продлятся сами) |
| Сетка мельчит пролив или залив (суша там, где было море) | `local` в `corrections/sea-levels.json`: многоугольник и местный уровень |
| Исчезнувшее озеро на древней карте | контур в `corrections/lakes/`, имя — в `lakes` в `corrections/sea-levels.json` |
| Карта разобрана не целиком | контур разобранных частей в `corrections/regions/`, запись в `regions` в `corrections/reviewed.json` |
| Сколько рек видно при каком масштабе, их толщина и цвет | `src/config.js` (`rivers`), `src/styles.css` (`.river`, `--river`) |

## Публикация на claude.ai

Хостинг артефактов сам добавляет обёртку `<html><head><body>`, поэтому
`tools/make-artifact.mjs` создаёт папку `dist-artifact/` с `index.html` без обёртки.
Остальные файлы публикуются рядом как есть. Ограничения хостинга: в адресе после `#`
допустимы только буквы, цифры и «-»; внешние скрипты только с разрешённых CDN
(поэтому библиотеки лежат локально).
