# Реестр зон — решение владельца 15.11 (план; применить в новом чате по «применяй»)

## Зачем
Одно место с исходными данными всех наших зон: когда культура жила, на каких картах стоит, какой там ареал и откуда он взят.
- **Новая карта** (основная или промежуточная): отбираем скриптом зоны, чьи начало и конец накрывают дату карты, — переносим или даём владельцу на проверку, не повторяя работу.
- **Страховка:** по реестру можно перестроить правила, если `corrections` где-то потеряются (главная страховка всё равно — git).
- Заменяет строки «Горизонт:» в пунктах очереди и файл `corrections/between-maps.md`.

## Решения владельца (15.11)
1. **Две таблицы** (TSV, UTF-8, открываются в Excel): `corrections/zones.tsv` — «Зоны», `corrections/zone-maps.tsv` — «Зона на карте».
2. **Главный — `corrections.json`**; реестр — его опись. Сборка проверяет совпадение (предупреждение, не ошибка).
3. **Даты заполняем сейчас** (из записей очередей), а не перед картой 5000.
4. Горизонт — не «целевая карта», а **годы существования** зоны; карты, ареал, источник ареала и название — на каждую карту.

## Таблица «Зоны» (`corrections/zones.tsv`) — строка на культуру / группу / область «Нет данных», «Не заселено», ледник
| Столбец | Что |
|---|---|
| key | постоянный ключ (латиницей, напр. `peiligang`), не меняется при переименованиях |
| Название | англ. / рус.; синонимы через «;» |
| Тип | культура / группа / памятник / Нет данных / Не заселено / ледник |
| Начало | число, календарный год (до н. э. — минус: −6200) |
| Начало — надёжность | по датам / по автору / не позже / неизвестно |
| Конец | число |
| Конец — надёжность | то же |
| Источник дат | база p3k14c (лабораторные номера) или публикация; исходные BP — здесь |
| Предшественник | текст модели + вывод («→ учтено: …», «→ key») |
| Преемник | то же |
| Статус | стоит / на проверку / между картами |
| Пункты | номера пунктов очередей (3-172, 6-225 …) |
| Примечание | |

Зона с неизвестным краем при новой карте идёт **на проверку**, а не переносится молча.

## Таблица «Зона на карте» (`corrections/zone-maps.tsv`) — строка на пару «зона × карта»
| Столбец | Что |
|---|---|
| key | из «Зон» |
| Карта | год карты (−10000, −8000, −6000 …) |
| id правила | id в `corrections.json` (`m6-…`) |
| NAME | название на этой карте (как в данных) |
| Русское | как в `translations/names/ru.json` |
| AREA / GROUP | область группы, если есть |
| Ареал | словами или «без изменений» |
| Контур | правило построения: памятники с координатами + правило границы (оболочка + 50 км, круг 35 км …) |
| Файл контура | `corrections/shapes/…` |
| Источник ареала | публикация / пункт очереди |
| Карточка | ключ примечания (NOTE) |

## Порядок работ (новый чат, после «применяй»)
1. **Каркас скриптом** (`tools/zones-registry.mjs`): из `corrections.json` — все правила-зоны с годами −10000, −8000, −6000 (удаления зон исходника не берём) → строки «Зона на карте» (id, годы, NAME, AREA/GROUP, файл контура, NOTE) и черновые строки «Зон» (ключи; одна зона на разных картах — один key: связывать по общему контуру, NOTE и записям «Горизонт», спорное — показать владельцу).
2. **Даты, ареал, контур, предшественники — из очередей** (`queue-map6000.md`, `queue-map8000.md`, `queue-map2.md` и `archive/`; номер пункта — в поле `why` правила): скрипт вытаскивает строки «Даты: сверено», «Контур:», «Горизонт:» в черновик, Claude сверяет и раскладывает. Ранние зоны 10 000 / 8000 (до правила 21.10) без записей — «неизвестно», дополнять, когда зона понадобится.
3. **Перенести `corrections/between-maps.md`** (М-1 … М-6, Азия-10) в «Зоны» строками без карт (статус «на проверку» / «между картами»); сам файл — в `_to_delete/`.
4. **Проверка при сборке** (`tools/check-zones.mjs`, как `check-colors.mjs`): у каждого правила-зоны карт −10000 … −6000 есть строка «Зона на карте», NAME совпадает, файл контура есть; зона в реестре без правила — предупреждение.
5. **Правила:** `CLAUDE.md` п. 9 (горизонт) и п. 24 (предшественники), `corrections/README.md` — горизонт = начало / конец в «Зонах»; в пункте очереди — строка «Горизонт: → реестр, key»; новые зоны и изменения — в реестр при применении пакета (вместе с `ru.json`, п. 23).
