# Реестр зон (решение владельца 15.11; запущен 15.11, этап 32)

## Зачем
Одно место с исходными данными всех наших зон: когда культура жила, на каких картах стоит, какой там ареал и откуда он взят.
- **Новая карта** (основная или промежуточная): скриптом отбираем зоны, чьи «Начало» и «Конец» накрывают дату карты, — переносим по записи или даём владельцу на проверку, не повторяя работу.
- **Страховка:** по реестру можно восстановить правила, если `corrections` где-то потеряются (главная страховка всё равно — git).
- Заменил строки «Горизонт:» в пунктах очереди (теперь — «Горизонт: → реестр, key») и файл `corrections/between-maps.md` (перенесён 15.11, старый файл — `_to_delete/between-maps-2026-11-15.md`).

## Решения владельца (15.11)
1. **Две таблицы** (TSV, UTF-8, открываются в Excel): `corrections/zones.tsv` — «Зоны», `corrections/zone-maps.tsv` — «Зона на карте».
2. **Главный — `corrections.json`**; реестр — его опись. Сборка проверяет совпадение (предупреждение, не ошибка): `tools/check-zones.mjs`.
3. **Даты заполняем сейчас** (из записей очередей), а не перед картой 5000. **Порядок (20:15):** сначала 6000, потом 8000 и 10 000 (следующие чаты).
4. Горизонт — не «целевая карта», а **годы существования** зоны; карты, ареал, источник ареала и название — на каждую карту.
5. **Карта 1 (123 000) — в реестре (20:15):** только имеющаяся информация; неизвестные концы — «неизвестно», поиска не делаем. Исторические карты (2000 до н. э. и позже) — не включаем, пока до них не дошли.

## Таблица «Зоны» (`corrections/zones.tsv`) — строка на зону
| Столбец | Что |
|---|---|
| key | постоянный ключ латиницей (`kunda`, `wilton`), не меняется при переименованиях |
| Название | англ. — названия на всех картах через «;» (последнее — первым), для области — «группа — область» |
| Русское | как в `translations/names/ru.json` (последняя карта) |
| Тип | культура / область группы / ареал вида (карта 1) / Не заселено / ледник / область (местные комплексы) — для записей без карты / памятник (с 17.11 — кандидат на будущую карту по одной стоянке) |
| Начало, Конец | календарный год (до н. э. — минус: −6200; н. э. — плюс: 1803) |
| … — надёжность | **по датам** (даты стоянок) / **по автору** (граница культуры у автора) / **не позже** (культура уже была — обычно первая карта, где стоит) / **не раньше** (ещё была — обычно «5000 — да» в горизонте) / **неизвестно** / **наводка (таблица модели)** |
| Источник дат | строка «Даты: сверено …» пункта очереди (с номером) или база p3k14c с лабораторными номерами |
| Предшественник, Преемник | «→ key» (зона реестра) или текст модели + вывод; «(контур или ареал перенесён)» — связь найдена по общему контуру / правилу |
| Статус | стоит / на проверку / между картами / на будущую карту (с 17.11 — зона из источников для следующих карт, без строк «Зона на карте»; вместо разделов «Заготовка» в очередях); снята (с 21.11, этап 44 — зона убрана со всех карт по решению владельца; строка остаётся для истории и ссылок, без строк «зона × карта») |
| Карты | годы карт, где зона стоит (сверяет сборка) |
| Пункты | номера пунктов очередей (3-172, 6-225, «п. 26» — карта 10 000, М-1 … — бывший `between-maps.md`) |
| Примечание | текст горизонта из очередей («Горизонт: [6-166] …»), пояснения к годам |

Зона с неизвестным краем (или краем в окне ±250) при новой карте идёт **на проверку**, а не переносится молча.

## Таблица «Зона на карте» (`corrections/zone-maps.tsv`) — строка на пару «зона × карта»
| Столбец | Что |
|---|---|
| key | из «Зон» |
| Карта | год карты (−123000, −10000, −8000, −6000, −5000) |
| id правила | id в `corrections.json` (одно правило на нескольких картах — по строке на карту) |
| NAME, AREA, GROUP | как в правиле (сверяет сборка) |
| Русское | как в `translations/names/ru.json` |
| Ареал | словами (из строки «Контур:» пункта); «(пункт … — общий для нескольких зон …)» — запись пункта описывает несколько зон, здесь — часть про эту |
| Контур | правило построения из пункта: памятники с координатами + правило границы (до 3 пунктов, «[6-166] …») |
| Файл контура | `shapes/….geojson` (сверяет сборка) |
| Источник ареала | пункт(ы) очереди |
| Карточка | ключ примечания (NOTE) (сверяет сборка) |
| Пункты | номера пунктов из поля `why` правила |

## Как сделан (15.11)
1. **Каркас** — `node tools/zones-registry.mjs init` из `corrections.json` (все правила-зоны карт −123000 … −6000). Одна зона на разных картах — один key: связка по общему контуру, по id правила (`m8-x` → `m6-x`), по id в `why` и по совпадению NAME + AREA. Пары с разными именами (90) решены 15.11: одно население с уточнённым именем — один key (32 пары); новая культура или период — разные key с «Предшественник» / «Преемник» (38 связей на соседних картах). Рабочие файлы — `Claude outputs/registry/` (`finalize.py`, `zones-disputed.tsv`).
2. **Карта 6000** (228 зон): годы — из строк «Горизонт:» и «Даты:» пунктов (`fill6000.py`): годы из записи → «по автору» / «по датам»; иначе «Начало» = первая карта зоны («не позже»), «Конец» = «не раньше −5000» при «5000 — да», «не позже −5250» при «5000 — нет», иначе «неизвестно». Итог по концу: по автору 54, по датам 6, не раньше 47, не позже 20, неизвестно 101. Ареал словами и правило контура — у 180 строк из 228 (у остальных записи «Контур» нет — «без изменений»).
3. **Карта 1** (30 зон): «Начало» — «не позже −123000», «Конец» — «неизвестно»; 8 зон «Не заселено» (Антарктида, Гренландия, острова Атлантики, Индийского океана, Северной Атлантики, Удалённая Океания, Галапагос, Балеары и Мальта) — те же зоны, что на 10 000 … 6000 (контур тот же).
4. **`between-maps.md`** (М-1 … М-6, Азия-10) — 6 строк «Зон» без карт (5 «на проверку», 1 «между картами»).
5. **Проверка при сборке** — `tools/check-zones.mjs` (вызывает `build-data.mjs`; можно и отдельно).

6. **Карты 8000 и 10 000** (этап 33, 15.11; `Claude outputs/registry/fillearly.py`, классификация горизонтов — `cls_early.py`): годы — у 203 зон, которых нет на 6000 (у остальных 103 зон этих карт годы заполнены на шаге 6000). «Начало» — «не позже» первой карты; «Конец»: годы из записей и карточек — «по датам» 51, «по автору» 17; в записи «на следующей карте — нет» или там уже другая зона (преемник) — «не позже» (следующая карта − 250 лет) 79; зона продолжается на 8000 под другим ключом — «не раньше −8000» 3; иначе «неизвестно» 53 («Нет данных» на следующей карте — не конец). Годы из карточки (`translations/notes/ru.json`) помечены в «Источнике дат» («карточка: …»). Ареал словами и контур — у 144 строк 8000 из 224 и у 26 строк 10 000 из 168 (у остальных записи «Контур» нет). Попутно: у Аямару и Пунтуджарпы «Начало» исправлено на «не позже −10000» (на шаге 6000 было взято начало фазы 6000).

Всего: 459 зон, 650 строк «зона × карта».

## Как вести
- **«Применяй»:** после правки `corrections.json` — `node tools/zones-registry.mjs add-missing` (дописывает строки «Зона на карте» для новых правил; key подставляется по NAME + AREA, иначе пустой), затем вручную: key, строка в «Зонах» (годы — по записи пункта: «Даты», «Горизонт»), «Ареал», «Контур», «Источник ареала». Изменённые NAME, AREA, файл контура, карточка — поправить в строке (сборка подскажет).
- **При разборе (с 17.11, владелец):** горизонты уже стоящих зон и строки без карт («на проверку», «между картами», «на будущую карту») Claude пишет сам, без «применяй»; новые зоны текущей карты — только при «применяй».
- **Пункт очереди:** строка «Горизонт: → реестр, key» и коротко что и почему; годы — в реестр при применении.
- **Новая карта:** отбор зон по «Начало» / «Конец» (скрипт — сделать при первой такой карте); неизвестный край или край в окне ±250 — владельцу.
