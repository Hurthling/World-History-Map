# Памятка для ИИ-помощника

Здесь — только действующие правила, коротко. Почему и когда они приняты — `docs/RULES-HISTORY.md` (поиск по слову или старому номеру пункта). Подробные процедуры — `corrections/README.md`. Разделы «Дописьменные карты» — для карт примерно до −3000; правила для исторических карт появятся отдельным разделом, когда дойдём до них.

## Общее

1. **Ничего не применять без прямой команды владельца «применяй».** Исправления и попутные находки — сначала в очередь (`corrections/queue-*.md`) или в «Следующие шаги» `PROGRESS.md`, с объяснением. Сомневаешься — переспроси. Без команды Claude ведёт сам только опись дат и реестр зон (горизонты стоящих зон, записи без карт); новые зоны текущей карты попадают в реестр только при «применяй».
2. Владелец не программист: объясняй простыми словами, по-русски, на «ты». Комментарии в коде — по-английски, документация — по-русски.
3. **Вход в чат:** из `PROGRESS.md` — шапка, «Текущее состояние» (с «Открыто») и «Следующие шаги»; затем этот файл; очередь — только свою (карта и часть света). `docs/ARCHITECTURE.md` — только при применении (код, сборка). `docs/HISTORY.md`, `docs/RULES-HISTORY.md`, `corrections/archive/` целиком не читать — искать по номеру пункта или слову.
4. Главный журнал — локальный `PROGRESS.md`. Записку `claude/PROGRESS.md` в проекте claude.ai **не обновлять**: каждое обновление сбрасывает кэш у чатов проекта.
5. После этапа обнови `PROGRESS.md`: «Текущее состояние» — одна запись не длиннее ≈ 15 строк плюс список «Открыто» (прежнюю запись — в начало «Журнала состояний» `docs/HISTORY.md`); в «Сделано» — два-три последних этапа. Подробности разбора — в архив, не в журнал.
6. Работай маленькими этапами; после каждого проект рабочий. Чат стал длинным — обнови журнал и очередь и предложи новый чат на естественной границе.
7. **Не делать:**
   - не заходить на researchgate.net (ни переходом из поиска, ни WebFetch) — нужна статья оттуда: название, авторы, год — владельцу;
   - не читать папку «Sources» подряд: только файл, названный владельцем или в пункте очереди, только нужные страницы, текст — командой;
   - не править руками `data/` и `src/vendor/` (пересборка — `npm run build-data`);
   - не отправлять на GitHub («Push origin» нажимает владелец);
   - не делать архивы `backup-*.tgz` (резервная копия = версия в git) и превью зон;
   - не убирать «Sources», «Claude outputs», «Suggestions» из `.gitignore`.

## Карты и части света

8. **Зоны рисуем целиком:** контур не режется по границам частей света и госграницам, только по суше. Части света задают лишь порядок разбора.
9. **Части света** — какая территория куда на какой карте: `docs/parts-of-world.md`. На 5000: «Россия и Кавказ» — вся Россия и весь Кавказ (Крым и другие спорные территории Украины — в Европе); Малайский архипелаг — в «Австралии и Океании»; Мальта — в Европе; Тринидад и Тобаго, Аруба, Кюрасао, Бонайре, Маргарита — в Южной Америке, остальная Вест-Индия — в Северной (с 4000 — вся в Южной).
10. **Порядок частей света на карте:** Южная Америка → Северная Америка → Австралия и Океания → Азия → Россия и Кавказ → Европа → Африка. Субрегионы — постоянная сетка «<Часть света>-N <имя>»: границы и метки не меняются от карты к карте (чтобы сравнивать карты поиском); разный вес субрегионов выравнивает разбивка на чаты (п. 23). Неудачный субрегион можно поделить на «-Nа / -Nб» без перенумерации.
11. **Номера пунктов:** с карты 5000 — «5000bc-N» (в чате можно просто номер), карта 6000 — «6-N», сайт — «С-N».
12. **Русские названия** — при применении, сразу в `translations/names/ru.json` (ключ — поле в данных буква в букву). Латинские названия видов не переводим; народы — во множественном числе с заглавной. Проверка — все NAME, SUBJECTO, PARTOF, AREA карты есть в `ru.json`.

## Дописьменные карты: пункты очереди

13. **В каждом новом пункте, до решения владельца:**
    - «Даты: сверено …» — даты как в источнике и источник (или база);
    - «Контур:» — словами для владельца, плюс памятники с координатами и правило границы для построения;
    - «Горизонт: → реестр, key: −6500 … −5400 (надёжность, источник) — дальше X» — в годах, а не в картах.

    При применении строим по записи, без повторного поиска. На следующую карту зона переносится по реестру без повторного разбора; заново — только при новых данных или если край в окне ±250 лет. **Перенос — с проверкой опор контура:** участок, который держат только памятники, кончившиеся до даты карты, молча не переносить — в «ОБЯЗАТЕЛЬНО» субрегиона (сжать или оставить по новым данным). Где в записи «Контур:» есть памятники с координатами — проверяет `node tools/check-anchors.mjs --year <год>` (по базе; памятники без дат в базе — по описи, глазами); у ранних зон без такой записи — край смотреть в чате.
14. **Даты — сначала из базы и описи:** `node tools/c14.mjs` по району и опись дат `corrections/source-dates.tsv` (всё, что уже прочитано в источниках, — файл второй раз не открывать); веб-поиск — только ради недостающих дат или места и для толкования. Даты из таблиц сторонних моделей — только наводки. Канада: даты CARD, которые решают пункт, сверять по CARD (С-12).
15. **Один источник на зону.** Второй — только если авторы спорят об атрибуции, датировке или ареале (по файлу на сторону); споры о другом — одной фразой в карточку или в реестр. Первым — обзор с таблицей дат и картой, а не отчёт о стоянке. Зонам «Нет данных» источник не нужен. Источник можно не открывать, если в базе по зоне ≥ 2 независимые даты «на дату» и атрибуция не под вопросом.
16. **Чтение по выдержкам:** скрипт (`python3 tools/vyderzhki.py`; он же определяет тип файла — текст, плохой слой, скан — и вес для разбивки на чаты; сканы распознаёт с `--ocr spa+eng` и т. п., языки — `Claude outputs/tessdata/`) выбирает места с датами (BP, cal, до н. э., лаб. номера, таблицы) и именами стоянок и культур зоны — читать с соседними абзацами. Целиком — только если скрипт ничего не нашёл, файл — скан, даты словами, вопрос об атрибуции или о надёжности дат (раковины, кость, керны). Выдержки хранить в `Claude outputs/<часть света>/chatN/` — во втором круге перечитывать их, а не извлекать заново.
17. **Попутно** в прочитанном источнике сверяй все даты со всеми картами: разобранные и разбираемая — пункт очереди; неразобранные — опись и реестр («на будущую карту»). Книги и сборники о других эпохах — только даты.
18. **Предшественники и преемники.** Преемников — в реестр («на будущую карту»), так же — короткие преемники (начались после текущей карты и кончились до окна следующей). Предшественников — по реестру и базе: «на дату» или «вилка» по источнику и базе — сразу пункт той карты; только название, одна дата или край окна — «Кандидаты на прошлые карты», проверка — в добивке своего чата. Названная культура, не проверенная на прошлую карту, — в реестр «на проверку»; проверенная, но не на дату, — «между картами». «Мезолит / неолит области X» — смотреть, есть ли на прошлой карте зона на ядре области X («Нет данных» — не зона). Культура или стоянка от владельца на будущую карту — проверить по его источникам самому (реестр, опись, добивочные вопросы); в промты на ту карту — только после проверки. Текст модели в таблице не заменять — дописывать вывод («→ учтено: …»).
19. Пункт «решать нечего» без комментария владельца — принят (молчание = согласие).
20. **Опись дат** (`corrections/source-dates.tsv`) — все даты прочитанного источника, только скриптом: `python3 tools/opis-add.py <файл TSV> "<дата (чат N)>"`; руками — только даты, по которым решается пункт. Большая таблица — строками, если извлекается чисто, иначе одной строкой «табл. N: K дат, диапазон». Расхождение с базой — сразу в разбор (влияет на пункт — в пункт). **Реестр зон** (`corrections/zones.tsv`, `corrections/zone-maps.tsv`; столбцы — `docs/zones-registry.md`) — одним заходом в конце чата по списку «в реестр».

## Дописьменные карты: работа с частью света

21. **Новая карта** — «Регламент начала новой карты» (`corrections/README.md`), читать при старте карты.
22. **Подготовка части света** — «Регламент подготовки части света» (README), промт — `docs/prompts-ai.md`. Вычёркивание таблицы — одним прогоном, без веб-поиска: на зону один [обязательный] файл и 1–2 [запасных]; оформление — README, «Помощь сторонних ИИ-моделей». Ошибки таблицы модели не перечислять — коротко писать, чего не хватает и что из-за этого не сверено.
23. **Разбивка на чаты** — окончательно в начале первого чата разбора, скриптом по файлам в папке (`python3 tools/vyderzhki.py info <папка>`, файлы не читаются); при вычёркивании — только предварительная раскладка. Вес — объём выдержек: ≈ 8 «средних» файлов на чат; скан или плохой текстовый слой — ×2–3 или по числу нужных страниц; файл, уже прочитанный для другого пункта, — 0; зоны с общим файлом — в один чат. Тяжёлый субрегион — отдельным чатом или двумя по зонам; лёгкие — вместе с соседями.
24. **Чат разбора:** (1) хвосты и короткая добивка прошлого чата; (2) разбор источников → пункты очереди; (3) проверка пустот (`node "Claude outputs/c14-outside.mjs" <год> W,S,E,N`) — каждая стоянка базы «на дату» и «вилка» в субрегионах чата объяснена (в зоне / кандидат / не на дату / ошибка координат / «Нет данных» с причиной); и обратная проверка — участки зон (перенесённых и новых) без дат на текущую карту; (4) добивка одним списком: скачать (название, авторы, год, зачем) / вопрос модели (готовым куском) / вопрос владельцу; кандидаты на прошлые карты — тут же, по базе и прочитанному. Попутные задачи (пункты С-…, разбор баз дат) — не здесь, отдельным чатом. В конце части света — сверка стыков субрегионов скриптом, без чтения.
25. **Вывод разбора.** Детальный разбор пишется один раз — в архив `corrections/archive/<карта>/<часть света>/<дата> <часть света>, чат N — <субрегионы>.md`; владельцу — карточкой файла и путём текстом. В чат — короткая таблица по возрастанию номеров: номер — зона — рекомендация — что решить (а / б) или «решать нечего». В файле у пункта: факты, варианты (прямо: «на выбор» или «идут вместе»), контур словами, горизонт.
26. **Очередь — только незакрытое:** строка на пункт (номер, зона, решение, ссылка на архив), «ждут решения», добивка, кандидаты; в шапке — последний номер. Применённое — удалить.
27. **Добивка — сразу, не копить.** Владелец отвечает в том же чате; зависящее от добивки — «отложено»: в архиве — блок «Отложено» (что сверено, чего ждём, какое решение зависит), в очереди — «отложено — ждёт X, архив, чат N». Короткая добивка — в начале следующего чата, длинная — отдельным чатом перед следующим разбором. Второй круг дописывается в тот же архивный файл («Круг 2, дата»), в «Отложено» — строка «→ закрыто, круг 2».
28. **Конец чата:** архив, очередь, реестр, запись в `PROGRESS.md` и **готовая фраза для начала следующего чата** (что разбирать, какие пункты добивки, какие файлы).

## Применение и публикация

29. Применять — по накоплению (≈ 30–40 пунктов или когда владелец хочет посмотреть); момент подсказывает Claude. Перед «применяй» — `git status`: есть несохранённое — сказать владельцу, версию он сохраняет сам.
30. **Порядок:** строить по записи пункта → новые и изменённые зоны в реестр (`node tools/zones-registry.mjs add-missing`) и `ru.json` → сборка `npm run build-data` → проверка (`node tools/serve.mjs` → http://localhost:8000; предупреждения `tools/check-zones.mjs`) → версия `git add -A && git commit` (в сообщении — что вошло) → владелец нажимает «Push origin». Рабочий `mapw-*.tgz` — удалить после пакета. Сайт — https://hurthling.github.io/World-History-Map/, лицензия GPL-3.0.
31. Применение обычно идёт на Sonnet: нестандартное (наложения, цвета, ошибки проверки) на ходу не решать — пунктом в очередь. Замечания по виду после применения — тоже новыми пунктами.

## Временные правила (со сроком)

- Старые записи «Горизонт:» в очередях и архиве (до 15.11, до реестра) — нужны при разборе, пока не разобраны Австралия и Океания и Европа на 5000; потом правило — в историю.
