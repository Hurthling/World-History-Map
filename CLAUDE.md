# Памятка для ИИ-помощника

0. **Главное правило (решение владельца 18.10):** никаких правок не применять, пока владелец прямым текстом
   не скажет это сделать. Всё — и исправления, и найденные попутно проблемы — сначала ставится в очередь
   (`corrections/queue-*.md` или раздел «Следующие шаги» в `PROGRESS.md`) с объяснением. Сомневаешься — переспроси.
   **Исключение (владелец 17.11):** вспомогательные файлы — опись дат (`corrections/source-dates.tsv`) и реестр зон (горизонты уже стоящих зон, записи без карт) — Claude ведёт сам, без команды; спрашивает только при сомнении. Новые зоны текущей карты попадают в реестр только при «применяй».
1. **Вход в чат (владелец 20.11, этап 42):** прочитай из `PROGRESS.md` только шапку «Для ИИ-помощника», «Текущее состояние» (с «Открыто») и «Следующие шаги» — остальные разделы по необходимости, поиском; затем этот файл. `docs/ARCHITECTURE.md` — когда трогаешь код или сборку (применение), в чатах разбора — не нужно. Очередь — только свою (по карте и части света).
   Главный журнал — только этот локальный `PROGRESS.md`. В проекте claude.ai лежит постоянная входная записка `claude/PROGRESS.md`
   (отсылает сюда) — **её не обновлять** (владелец 31.10, С-6: каждое обновление сбрасывает кэш у чатов проекта).
   История этапов (`docs/HISTORY.md`) и архив очередей (`corrections/archive/`) целиком не читай — ищи нужное по номеру
   пункта или слову.
2. Владелец не программист: объясняй простыми словами, по-русски. **Общаемся на «ты»** (решение владельца 21.10).
3. Работай маленькими этапами; после каждого проект должен оставаться рабочим.
4. После этапа обнови `PROGRESS.md`: что сделано, решения и почему, следующий шаг. **«Текущее состояние» — одна запись, не длиннее ≈ 15 строк, плюс список «Открыто»** (владелец 20.11, этап 42; раньше — три записи): прежнюю запись переноси в `docs/HISTORY.md`, «Журнал состояний» (в начало списка). Подробности разбора — в архиве очереди, не в журнале. В «Сделано» — два-три последних этапа, остальные — в `docs/HISTORY.md`.
5. Не правь руками `data/` и `src/vendor/`: данные пересобираются `npm run build-data`.
6. Комментарии в коде на английском, документация на русском.
7. Проверка: `node tools/serve.mjs` → http://localhost:8000
8. Следи за длиной чата: когда он становится длинным (обычно после завершения карты или большого пакета правок),
   обнови `PROGRESS.md` и предложи владельцу начать новый чат.
9. **Горизонт применения (владелец 21.10):** разбирая зону, сразу записывай в очередь строку «Горизонт:» — на каких
   следующих картах она стоит и в каком виде, где кончается и почему. На следующей карте такие зоны переносятся по записи,
   без повторного разбора. Уже разобранные зоны задним числом не перепроверяем — горизонт им пишем, когда до них дойдём.
   Подробно — `corrections/README.md`, «Правила работы с древними картами». **С 15.11 горизонт — в реестре зон** (п. 25): годы «Начало» / «Конец» и текст горизонта — в `corrections/zones.tsv`, в пункте очереди — «Горизонт: → реестр, key» и коротко что и почему. **Горизонт — в годах, а не в картах** (правило 05.11, `corrections/README.md`, «Источники целиком», (3); напоминание владельца 18.11): «Горизонт: → реестр, key: −6500 … −5400 (надёжность, источник) — дальше X»; какие карты захватит зона — считает отбор по реестру.
10. **Даты и контур — при разборе (владелец 21.10):** в каждом новом пункте очереди, до решения владельца, — строки
    «Даты: сверено …» и «Контур:» (словами для владельца + памятники с координатами и правило границы для построения).
    При применении строй по записи, без повторного поиска. Подробно — `corrections/README.md`.
11. **Даты — сначала из базы:** `node tools/c14.mjs` (база p3k14c + калибровка) по району, веб-поиск — только для
    недостающего и толкования. Подробно — `corrections/README.md`.
12. **Папка «Источники» (владелец 21.10):** туда владелец складывает скачанные статьи, диссертации и т. п. Сам её не читай;
    открывай только файл, на который указал владелец или который назван в пункте очереди, и только нужные страницы
    (текст извлекать командой, а не загружать файл целиком).
13. **Разбор — в чат (владелец 24.10):** после разбора новые пункты очереди выводи в чат текстом, а не только в файл. Для каждого
    пункта: номер и название зоны; факты кратко (даты, что найдено); твои предложения (варианты, рекомендация); решения, которые нужны
    от владельца; контур словами; горизонт. Координаты и правила построения — только в файле очереди. Подробно — `corrections/README.md`. **Пункты — строго по возрастанию номеров очереди** (владелец 26.10: иначе легко пропустить пункт). Несколько предложений в пункте — прямо писать: «варианты на выбор» или «идут вместе, не выбор» (владелец 29.10).
14. **Публикация (владелец 26.10):** сайт — GitHub Pages (https://hurthling.github.io/World-History-Map/), лицензия GPL-3.0. После применённого пакета:
    сборка → проверка → версия в git (`git add -A && git commit`, сообщение — что вошло в пакет) → владелец нажимает «Push origin» в GitHub Desktop.
    Сам на GitHub не отправляй (доступа нет и не нужно). Папки «Источники», «Claude outputs» и «Разборы» (рабочие Excel-таблицы частей света — владелец 19.11) в git не попадают (`.gitignore`) — не убирай их оттуда.
    **Резервные копии (владелец 27.10, С-4):** архивы `backup-before-*.tgz` не делать — резервная копия = версия в git. Перед «применяй» проверь `git status`: если есть
    несохранённые изменения (обычно очереди и `PROGRESS.md` после разбора) — **скажи владельцу, он сохранит версию сам**, и только потом применяй. Рабочий архив
    `mapw-*.tgz` (перенос в облако для сборки) — удалить после пакета.
15. **Попутный разбор источников (владелец 02.11):** в источнике владельца сверяй все даты со всеми картами: по разобранным и разбираемым картам — полноценная проверка и пункт очереди, по неразобранным — с 17.11 не заготовка, а опись дат и реестр (статус «на будущую карту»). Подробно — `corrections/README.md`.
16. **Проверка пропусков «база против зон» (владелец 02.11):** при разборе новой части света на 6000\* сверяй базу дат с зонами и на 10 000 и 8000 (10 000 — почти целиком; 8000 — Африка и Америки, остальное — только явные пропуски).
    Прогон — `node "Claude outputs/c14-outside.mjs" <год> W,S,E,N`; каждую точку сверяй по источнику. Подробно — `corrections/README.md`.
17. **Решения владельца 06.11:** пункт с пометкой «решать нечего», не прокомментированный владельцем, — принят (молчание = согласие); книги и сборники о других эпохах — только даты; с карты 5000 «часть света» — вся Россия и весь Кавказ (европейская часть России присоединяется к Сибири и Дальнему Востоку; Крым и другие спорные территории Украины — в Европе). Подробно — `corrections/README.md`.
18. **Решение владельца 07.11:** с карты 5000 Малайский архипелаг (Индонезия, Филиппины, весь Калимантан, Восточный Тимор) — в «части света» Австралия и Океания; на 10 000, 8000 и 6000\* — по-старому (в Азии). Подробно — `corrections/README.md`.
19. **ResearchGate — не открывать (решение владельца 07.11):** на researchgate.net сам не заходи (ни поиском-переходом, ни WebFetch): владельца временно заблокировали за автоматизированные запросы. Если нужна статья оттуда — напиши владельцу (название, авторы, год), он скачает сам или найдёт в другом месте. Подробно — `corrections/README.md`.
20. **Сторонние ИИ-модели (решение владельца 08.11):** разбор части света начинается с запроса владельца — Claude даёт субрегионы, по каждому строку «Район» с меткой, готовый диапазон и блоки «ОБЯЗАТЕЛЬНО включи» / «НЕ повторяй» для промта `docs/prompts-ai.md` (с 12.11 — один промт на субрегион: культуры и памятники в одной таблице); владелец прогоняет его через стороннюю модель и возвращает Excel (один лист) и скачанные источники. Даты из таблиц — только наводки: «Даты: сверено» — по тексту источника или базе. Столбец ссылок не использовать. Ошибки таблицы не перечислять — коротко писать владельцу, чего не хватает (нет файла, нет даты в источнике) и что из-за этого не сверено (владелец 12.11). С 14.11: в файле подготовки — полные промты; в «ОБЯЗАТЕЛЬНО» — только пробелы, меняющие карту; источники с датами, картой, ареалом — первыми; таблица сначала приходит без источников — Claude «вычёркивает» строки и даёт список «строка → 1–2 файла скачать». **С 15.11: вычёркивание — без веб-поиска** — по базе, прошлым решениям и файлам в папке; существование источников в интернете не проверять (ошибку модели владелец поймает при скачивании и переспросит); если строку без файла не решить — так и писать: «решится по файлу X». **С 20.11:** источники в файле вычёркивания нумеруются («1) … 2) …») с метками [обязательный] / [дополнительный] / [по желанию] / [уже есть], ссылки в столбце «Ссылка» — с теми же номерами. Нумеровать работы и ссылки просит и шаблон промта (`docs/prompts-ai.md`). Поиск — только при разборе и только ради дат или места. Подробно — `corrections/README.md`, «Помощь сторонних ИИ-моделей».
21. **Предшественники, преемники и источники на будущее (решение владельца 12.11):** разбирая культуру, записывай её преемников (с источниками из папки) в реестр — статус «на будущую карту» (до 17.11 — заготовка следующей карты), а предшественников — проверяй по прошлым картам (записи «Горизонт:» и база; попали в окно — пункт очереди). Если владелец дал культуру или стоянку, подходящую на следующую карту, вместе с источниками — проверяй её даты по этим источникам сам, без напоминания, пиши в реестр и опись («Даты: сверено …» для той карты) и задавай владельцу добивочные вопросы, если чего-то не хватает. Такие культуры и стоянки в промты для сторонних ИИ на ту карту не включай, пока Claude их не проверил (после проверки — в «НЕ повторяй» или «ОБЯЗАТЕЛЬНО включи — нужно: …»). **С 15.11 (владелец):** при разборе таблицы части света — отдельный список **«Кандидаты на прошлые карты»** (из графы «Предшественник / преемник», ранних фаз памятников, дат вне окна) с данными базы — на проверку владельцу; пунктом очереди кандидат становится по его решению. Так — по каждой части света; Сибирь — дополнительно задним числом (после Азии). **С 17.11** — по регламенту (п. 27): «на дату» или «вилка» по источнику и базе — сразу пункт; только название, одна дата или край окна — «Кандидаты»; проверка — этапом «Прошлые карты» в конце части света.
22. **Зоны рисуем целиком (решение владельца 12.11):** контур зоны не обрезается по границам частей света и современным госграницам — части света только задают порядок разбора; обрезка — только по суше. Подробно — `corrections/README.md`.
23. **Русские названия — вместе с разбором карты (решение владельца 13.11, С-7):** названия на карте переводим, когда карта проверена или проверяется (готово: 123 000, 10 000, 8000, 6000\*); новые названия зон — сразу в `translations/names/ru.json` при применении пакета (ключ — поле в данных буква в букву, стоянки — как в русском примечании). Латинские названия видов не переводим (Homo sapiens, Homo erectus …); неандертальцы, денисовцы — по-русски; народы — во множественном числе с заглавной («Делавары»). Проверка покрытия — все NAME, SUBJECTO, PARTOF, AREA карты есть в `ru.json`.
24. **Предшественники и промежуточные карты (решение владельца 15.11):** по графе «Предшественник / преемник» таблицы части света: **названная культура** — проверял ли её Claude на прошлую карту (очереди и архив, по всем синонимам из строки); не проверял — запись «на проверку»; проверял, но не на дату — запись «между картами» без новой проверки. **«Мезолит / неолит области Х»** — есть ли на прошлой карте зона, покрывающая ядро области Х («Нет данных» — не зона): есть — учтено, не проверяем; нет — «на проверку». Так же — **короткие преемники**: начались после текущей карты и кончились до окна следующей. Каждой записи — горизонт. Текст модели в графе не заменять — дописывать вывод («→ учтено: …», «→ М-N»). Записи — строками реестра `corrections/zones.tsv` без карт (статус «на проверку» / «между картами»; бывшие М-1 … М-6 перенесены 15.11); смотреть при промежуточной карте или проверке списка. Ведём с Азии и Сибири на 6000\*: по Азии записи проверяем вместе после разбора всей Азии, Сибирь — задним числом; остальные части света и горизонты — только попутно. Подробно — `corrections/README.md`.
25. **Реестр зон (решение владельца 15.11; запущен 15.11):** `corrections/zones.tsv` — строка на зону (годы существования с надёжностью, предшественник, преемник, статус «стоит» / «на проверку» / «между картами»), `corrections/zone-maps.tsv` — строка на «зону × карту» (правило, NAME, ареал словами, правило контура, источник ареала, карточка); карты 123 000, 10 000, 8000, 6000\*. Главный — `corrections.json`, реестр — опись; сборка сверяет (`tools/check-zones.mjs`, предупреждения). **При «применяй»** новые и изменённые зоны — сразу в реестр (`node tools/zones-registry.mjs add-missing`, ключ и строка зоны — вручную по записи пункта), вместе с `ru.json` (п. 23). **Новая карта:** отбор зон по «Начало» / «Конец»; неизвестный край или край в окне ±250 — владельцу на проверку. Годы заполнены для всех четырёх карт (8000 и 10 000 — 15.11, этап 33; ранние зоны без записей — «неизвестно»). Столбцы и значения — `docs/zones-registry.md`. С 17.11 — статус «на будущую карту» (вместо заготовок); горизонты стоящих зон и записи без карт — без команды (п. 0).
26. **Опись дат из источников (решение владельца 16.11):** все даты, встреченные при чтении источника (по любой карте), — в `corrections/source-dates.tsv`: строка на дату или группу дат (источник, стоянка, район, дата как в источнике, лаб. номер, материал, калиброванная, окна наших карт, культура, оценка, есть ли в базе, где учтено). Калибровка и окна — скриптом; большая таблица — строками, если извлекается чисто, иначе одной строкой «табл. N: K дат, диапазон». Это опись для промежуточных карт, а не решение. Окна — −10000, −8000, −6000, −5000 (с 17.11). Подробно — `corrections/README.md`, «Опись дат из источников».
27. **Регламент обработки таблицы части света (решение владельца 17.11):** исходные данные — вычеркнутая таблица и источники («обрабатывай»). Шаг 0 — разбивка по чатам (2–3 соседних субрегиона). В каждом чате: 1 — хвосты («ждать таблицу»); 2 — разбор источников **по выдержкам, один файл на зону** (п. 29; пункты очереди; прошлая карта: «на дату» / «вилка» по источнику и базе — сразу пункт, иначе — «Кандидаты»); 3 — проверка пустот по базе на текущую карту (каждая стоянка объяснена); 4 — добивка одним списком (скачать / вопрос модели / вопрос владельцу); круг — шаги 2 и 4. Шаг 5 — «Прошлые карты»: **с 20.11 — по регионам, в добивке своего чата** (п. 29); в конце части света — только сверка скриптом по стыкам (Африка — отдельным этапом по накопленным кандидатам чатов 1–6). Опись и реестр — попутно, без команды (п. 0). Применять — **по накоплению** (с 20.11; п. 29), момент подсказывает Claude. **С 19.11 (владелец): вычёркивание — одним прогоном** по всей таблице части света (владелец присылает её целиком, Claude вычёркивает в одном чате); разбор — как сейчас, по 2–3 субрегиона в чате. Подробно — `corrections/README.md`, «Регламент обработки таблицы части света».
28. **Регламент подготовки части света (решение владельца 19.11):** до регламента обработки (п. 27); условие — решённое по прошлой части света применено. Шаг 0 — хвосты, реестр (концы прошлой карты неизвестны или в окне ±250; «на будущую карту», «на проверку», «между картами»), опись и база на текущую карту (`c14-outside.mjs`, только список, без сверки по источнику) — скриптами; раскладка: даты уже сверены по прочитанному источнику → сразу пункт очереди; прогноз или пробел → «ОБЯЗАТЕЛЬНО»; нужный файл известен → «скачать сейчас»; разобрано → «НЕ повторяй». Шаг 1 — субрегионы с метками и границами части света, сразу сгруппированные по 2–3 для чатов разбора (с 21.11 — постоянная сетка субрегионов, группировка по чатам — заново на каждой карте, п. 30). Шаг 2 — файл подготовки: полные промты, подогнанные к части света (ссылки, языки, индустрии и фазы, смысл «неолита»), и раздел «Для тебя». Шаги 0–2 — одной выдачей в одном чате. Шаг 3 — владелец прогоняет промты, присылает одну таблицу без источников, параллельно качает «скачать сейчас». Шаг 4 — вычёркивание одним прогоном. Шаг 5 — владелец качает файлы и пишет «обрабатывай» → п. 27. Подробно — `corrections/README.md`, «Регламент подготовки части света»; промт — `docs/prompts-ai.md`.
29. **Экономный режим (решения владельца 20.11, этап 42; ретроспектива по расходу на Африке):** (1) **вход в чат** — п. 1, журнал — п. 4; (2) **один файл на зону:** при вычёркивании — один [обязательный] файл и 1–2 запасных по порядку («не скачается — следующий»), в папке — только один; второй файл — только если авторы спорят об **атрибуции, датировке или ареале** (графа «Споры» таблицы) — по файлу на сторону; споры о другом (материальная культура, будущий горизонт, названия) — в карточку одной фразой, в реестр или пропуск; не хватило — добивка; зонам «Нет данных» источник не нужен; первым — обзор с таблицей дат и картой, а не отчёт о стоянке; (3) **чтение по выдержкам:** скрипт выбирает из текста места с датами (BP, cal, до н. э., лаб. номера, таблицы) и именами стоянок и культур зоны, читаются они с соседними абзацами; **целиком** — если скрипт ничего не нашёл, файл — скан, даты словами, вопрос об атрибуции или о надёжности дат (раковины, кость, буровые керны); источник можно не открывать, только если в базе по зоне ≥ 2 независимые даты «на дату» и атрибуция не под вопросом; (4) **очередь — только незакрытое:** строка на пункт (номер, зона, решение, ссылка на архив), «ждут решения», добивка, кандидаты; применённое удаляется; **детальный разбор пишется сразу в архив** `corrections/archive/<карта>/<часть света>/<дата> <часть света>, чат N — <субрегионы>.md` (в чат — так же подробно, как раньше); указатель — `corrections/archive/README.md`; (5) опись дат — скриптом (руками — только даты, по которым решается пункт); реестр — одним заходом в конце чата по списку «в реестр»; (6) **прошлые карты — в добивке своего чата:** кандидаты сразу проверяются по базе и прочитанному источнику → пункт 8000 / 10 000 или «скачать»; в конце части света — сверка скриптом по стыкам субрегионов (контуры через границу чатов, цвета), без чтения; (7) ≈ 10 файлов на чат, больше — делить; (8) применение — по накоплению (≈ 30–40 пунктов или когда владелец хочет посмотреть); замечания по виду — новыми пунктами после применения. Подробно — `corrections/README.md`, «Экономный режим».
30. **Регламент начала новой карты (решение владельца 21.11):** для дописьменных карт, с 5000; идёт до регламента подготовки первой части света (п. 28). **Шаг 0 — условия и устройство карты:** прошлая карта закрыта (решённое применено, вопросы при её создании закрыты; добивка «по желанию» не мешает), версия в git сохранена; части света — с 5000 по пп. 17–18, Мальта — в Европе (владелец 21.11; контуры рисуются один раз); **порядок частей света — соседями, чтобы сразу покрывать стыки:** Южная Америка → Северная Америка → Австралия и Океания → Азия → Россия и Кавказ → Европа → Африка; **субрегионы — постоянная сетка на все карты** (метки «<Часть света>-N <имя>» не меняются; новые части света 5000 — сетка рисуется один раз), **группировка по чатам — заново на каждой карте** по нагрузке (перенесённые зоны, «ОБЯЗАТЕЛЬНО», стоянки базы на дату); **неразобранные части света — «Нет данных» вне перенесённых зон и оставленных зон исходника**, под годом подпись «Черновик: разобраны …» (список растёт, снимается, когда разобрана вся карта; меняет правило 20.10 для карт с 5000); **сайт — выкладываем по ходу**. **Шаг 1 — уровень моря, замкнутые моря, исчезнувшие озёра, ледники:** общий уровень; Каспий, Чёрное, Балтика; озёра (Мега-Чад, озёра «зелёной Сахары»); места, где берег шёл дальше нынешнего вглубь суши (низовья Тигра и Евфрата, поднятие суши в Скандинавии и у Гудзонова залива — сначала проверить, умеет ли сборка); остатки ледников и «Не заселено» подо льдом; подпись под годом. **Шаг 2 — перенос с прошлой карты по реестру:** «Начало» ≤ дата карты ≤ «Конец» — переносим по записи; **конец неизвестен или раньше даты карты — не переносим, зона — в «ОБЯЗАТЕЛЬНО» своего субрегиона**; конец в окне +250 после даты — переносим, край проверяем при разборе своей части света; карточки переносимых зон перечитать, устаревшее — в новые ключи `…-<год>` (RU и EN); «Не заселено» — отдельным списком (части одной зоны могут кончаться в разное время). **Шаг 3 — новые зоны из реестра («на будущую карту») и описи дат:** даты сверены по прочитанному источнику — пункт очереди, иначе — «ОБЯЗАТЕЛЬНО»; предшественники — по п. 24. **Шаг 4 — зоны исходника** (после шагов 2–3, чтобы видеть, где уже стоит наша зона): убрать / оставить / кандидат; исходник бывает анахроничен — «оставить» только со строкой «Даты: сверено …» и горизонтом; кандидат — в «ОБЯЗАТЕЛЬНО» субрегиона. **Шаг 5 — проверка:** сборка; реестр сходится; цвета (одинаковые не ближе 2000 км); русские названия (и у оставленных зон исходника); наложения наших зон на зоны исходника; «стоянка в своей зоне». Шаги 1–5 — пунктами очереди и одним пакетом по «применяй»; карта сразу выходит на сайт черновиком с подписью. **Шаг 6** — регламент подготовки первой части света (п. 28). Подробно — `corrections/README.md`, «Регламент начала новой карты».
