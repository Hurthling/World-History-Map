# Памятка для ИИ-помощника

0. **Главное правило (решение владельца 18.10):** никаких правок не применять, пока владелец прямым текстом
   не скажет это сделать. Всё — и исправления, и найденные попутно проблемы — сначала ставится в очередь
   (`corrections/queue-*.md` или раздел «Следующие шаги» в `PROGRESS.md`) с объяснением. Сомневаешься — переспроси.
1. Сначала прочитай `PROGRESS.md` (состояние и следующие шаги), затем `docs/ARCHITECTURE.md`.
   История этапов (`docs/HISTORY.md`) и архив очередей (`corrections/archive/`) целиком не читай — ищи нужное по номеру
   пункта или слову.
2. Владелец не программист: объясняй простыми словами, по-русски. **Общаемся на «ты»** (решение владельца 21.10).
3. Работай маленькими этапами; после каждого проект должен оставаться рабочим.
4. После этапа обнови `PROGRESS.md`: что сделано, решения и почему, следующий шаг.
5. Не правь руками `data/` и `src/vendor/`: данные пересобираются `npm run build-data`.
6. Комментарии в коде на английском, документация на русском.
7. Проверка: `node tools/serve.mjs` → http://localhost:8000
8. Следи за длиной чата: когда он становится длинным (обычно после завершения карты или большого пакета правок),
   обнови `PROGRESS.md` и предложи владельцу начать новый чат.
9. **Горизонт применения (владелец 21.10):** разбирая зону, сразу записывай в очередь строку «Горизонт:» — на каких
   следующих картах она стоит и в каком виде, где кончается и почему. На следующей карте такие зоны переносятся по записи,
   без повторного разбора. Уже разобранные зоны задним числом не перепроверяем — горизонт им пишем, когда до них дойдём.
   Подробно — `corrections/README.md`, «Правила работы с древними картами».
10. **Даты и контур — при разборе (владелец 21.10):** в каждом новом пункте очереди, до решения владельца, — строки
    «Даты: сверено …» и «Контур:» (словами для владельца + памятники с координатами и правило границы для построения).
    При применении строй по записи, без повторного поиска. Подробно — `corrections/README.md`.
11. **Даты — сначала из базы:** `node tools/c14.mjs` (база p3k14c + калибровка) по району, веб-поиск — только для
    недостающего и толкования. Подробно — `corrections/README.md`.
12. **Папка «Источники» (владелец 21.10):** туда владелец складывает скачанные статьи, диссертации и т. п. Сам её не читай;
    открывай только файл, на который указал владелец или который назван в пункте очереди, и только нужные страницы
    (текст извлекать командой, а не загружать файл целиком).
13. **Разбор — в чат (владелец 24.10):** после разбора новые пункты очереди выводи в чат текстом, а не только в файл. Для каждого
    пункта: номер и название зоны; факты кратко (даты, что найдено); твои предложения (варианты, рекомендация); решения, которые нужны
    от владельца; контур словами; горизонт. Координаты и правила построения — только в файле очереди. Подробно — `corrections/README.md`.
14. **Публикация (владелец 26.10):** сайт — GitHub Pages (https://hurthling.github.io/World-History-Map/), лицензия GPL-3.0. После применённого пакета:
    сборка → проверка → версия в git (`git add -A && git commit`, сообщение — что вошло в пакет) → владелец нажимает «Push origin» в GitHub Desktop.
    Сам на GitHub не отправляй (доступа нет и не нужно). Папки «Источники», «Claude outputs» в git не попадают (`.gitignore`) — не убирай их оттуда.
